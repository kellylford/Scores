# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

This repo contains two separate applications sharing a common purpose (sports scores with strong accessibility focus):

1. **Python desktop app** (Windows, PyQt6) — files in the repo root
2. **iOS app** (SwiftUI, iOS 17+) — files under `iOS/SportsScoresApp/`

Active iOS development happens on the `iOS` branch. The `main` branch holds the Python app.

## Python desktop app

### Running and testing

```bash
# Run the app
python scores.py

# Run all tests
pytest tests/

# Run a single test file
pytest tests/unit/test_simple.py

# Run a specific test
pytest tests/unit/test_simple.py::test_name
```

### Architecture

The Python app is a single-process PyQt6 application. `scores.py` is both the entry point and the main UI module — it contains all screen classes and navigation logic.

**Data flow:** `scores.py` → `services/api_service.py` → `espn_api.py` → ESPN API / MLB Stats API

- `espn_api.py` — all HTTP calls to `site.api.espn.com` (games, news, standings, schedules) and `statsapi.mlb.com` (MLB statistics). The MLB Stats API is used instead of ESPN for baseball stats because it's faster and covers full seasons.
- `services/api_service.py` — thin wrapper around `espn_api` that converts exceptions to `ApiError`
- `models/` — pure data classes: `game.py`, `news.py`, `standings.py`
- `accessible_table.py` / `accessible_table_core.py` / `accessible_table_widget.py` — accessible table widgets supporting three view modes (Table, Quick List, Full List) switchable via Alt+V/Alt+T/Alt+Q/Alt+F
- `simple_audio_mapper.py` / `stereo_audio_mapper.py` — pitch-to-audio spatial mapping for baseball
- `timezone_utils.py` — converts ESPN UTC timestamps to local time
- `windows_notifications.py` — Windows UIA live region announcements
- `exceptions.py` — `ApiError`, `DataModelError`

**Building the Windows executable:**
```bat
build-enhanced.bat   # full build with venv setup
build.bat            # quick PyInstaller build
```

**Development archive:** `TheBench/` contains exploratory scripts, API analysis tools, and old test files. Don't modify files there during normal development.

## iOS app

### Building

Open `iOS/SportsScoresApp/SportsScores.xcodeproj` in Xcode. The project file is generated by XcodeGen from `iOS/SportsScoresApp/project.yml` — if you add new Swift files, add them to `project.yml` and regenerate (`xcodegen generate` from `iOS/SportsScoresApp/`), then commit both files.

Target: iOS 17.0+, Swift 5.9, SwiftUI.

### Architecture

MVVM with SwiftUI. `AppSettings` is an `ObservableObject` injected via `.environmentObject` at the root in `SportsScoresApp.swift`.

**Three-tab root** (`ContentView.swift`):
- **Scores** → `SportSelectionView` (home) → `ScoresView` (per-sport) → `GameDetailView`
- **The Bench** → `TheBenchView` (venue tours, pitch zone explorer, audio tools)
- **Settings** → `SettingsView`

**Key directories:**
- `Views/` — SwiftUI views; `Views/Components/` for reusable pieces
- `ViewModels/` — one ViewModel per screen, all `@MainActor ObservableObject`
- `Models/` — `Game.swift`, `Sport.swift`, `Standings.swift`, `ESPNAPIResponseModels.swift`, etc.
- `Services/ESPNAPIService.swift` — singleton `async/await` ESPN API client (three ESPN base URLs: `site/v2`, `v2` for standings, `core/v2` for leaders/calendars)
- `Services/PitchAudioEngine.swift` / `FieldAudioEngine.swift` — AVAudioEngine-based spatial audio
- `Services/TouchTourAnnouncementService.swift` — VoiceOver announcement helper
- `Settings/AppSettings.swift` — `@AppStorage`-backed user preferences

**Data sources:**
- `https://site.api.espn.com/apis/site/v2/sports` — scoreboards, news, team schedules
- `https://site.api.espn.com/apis/v2/sports` — standings
- `https://sports.core.api.espn.com/v2/sports` — statistical leaders, season calendars, week ranges

### Design Principles

**`DESIGN_PRINCIPLES.md` is the canonical design reference** for the iOS app. Read it before implementing or changing any display or accessibility behavior. Key rules summarized:

- **Sport Screen Scores tab** must have exactly three sections in order: In Progress → Upcoming → Completed. Empty sections are omitted entirely (no placeholder text). This is currently unimplemented in `ScoresView` — it's the highest-priority gap.
- **Time period navigation**: non-football sports navigate by day; NFL/NCAAF navigate by week using ESPN-resolved week labels.
- **Team names on screen**: always use `abbreviation`. In VoiceOver labels: use `Game.Team.voiceOverName(for:)` which reads the user's `TeamNamePreference` setting. Never hard-code abbreviations into VoiceOver labels.
- **VoiceOver redundancy**: status words ("Final", "Live") must be hidden from VoiceOver inside sections that already convey that status via their heading.
- **Date navigation toolbar pattern**: Previous button · Date/Week label (with `.accessibilityAdjustableAction`) · Next button · Today button (hidden when already on today).
- **Play-by-play order**: what happened → when (clock) → score impact. Both visual and VoiceOver must follow this order.
